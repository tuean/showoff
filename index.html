主旨

为什么是现在 · 为什么是这些技术

软件正在从「买来的标准件」，变成为你一个人现场生成的那一件。

01 · 按需生成

不再迁就通用软件

写软件的成本一旦低于适应软件的成本，选择就反过来了。与其学一套为千万人设计的交互、 再忍受大半用不上的功能，不如把自己这台机器上的一天描述清楚， 直接拿到一个只包含我要的功能的版本。

所以这批东西大多没有产品经理、没有用户调研、也没有向下兼容的包袱——它们只有一个用户。 pdf2str 58 行、utools-selfie 打包 9 KB，这类东西不值得立项，但值得存在。

02 · 新栈优先

Rust 这类技术，账算得过来

写代码的边际成本被 AI 压下来之后，选型的约束就从「团队熟不熟悉」变成「机器跑不跑得动」。 Rust 的收益在这批软件上是能数出来的：没有 GC 抖动、常驻内存低、单个二进制没有运行时依赖、启动即用。

代价当然也有：IMAP、SMTP、MIME 一行一行手写下来，才有 maildesk 5.4 MB 的二进制和 3.6 万封邮件 94 MB 的常驻内存；treq 3.3 万行换来的同样是一个可以直接拷走的二进制。 小，意味着它值得一直开着——而不是用完就关。

treq

API Client · Rust + GPUI

本地优先的接口调试客户端：界面像 Insomnia，数据是磁盘上一堆能进 Git 的 YAML。

左边是空间 → 集合 → 分组（任意层级）→ 请求的树，中间编辑，右边看响应。 五种 Body、四种认证、JSON 高亮与折叠、状态码 / 耗时 / 大小、JSON 路径提示、cURL 导入与代码生成。 285 个测试函数和每次改动后的截图自检，是它敢连续重构的前提。

maildesk

Mail Client · Rust + GPUI

原生 macOS 邮件客户端：没有 WebView，没有现成邮件库，IMAP/SMTP/MIME 全部手写。

它只回答一个问题：一个邮件客户端能有多小。3.6 万封邮件实测 94 MB 物理内存、空闲 0.3% CPU、5.4 MB 二进制。 HTML 正文用真实文本排版渲染——标题、列表、表格、引用回复、内联图片，还能拖选复制。

artifeeds

Feed Reader · Rust + GPUI

为「上千个源、又快又省」写的桌面 RSS / Atom / JSON Feed 阅读器。

单定时器调度、两级预算并发、条件请求（没更新就只花一个 304、零字节正文）、自适应轮询，每个队列都有硬上限。 三种浏览维度（按博客 / 标签 / 分类）全部虚拟化。 还能让本机 pi 把任意网页变成订阅：一个 OPML 落地 102 个源 / 12 个分组。

18.0k 行 Rust 已装 /Applications pi 集成
构建轨迹：pi 项目记忆 + dsh 2 个会话

TVA

Voice Agent · Rust + GPUI

按住一个键说话，本机的 pi / dsh / opencli 替你动手。

whisper.cpp 完全离线识别，tiny 出实时预览、small 出终稿（解码耗时 0.15s / 0.9s）。 一条指令拆成录音 → 识别 → 理解 → 思考 → 执行 → 完成六步，每步耗时都来自真实信号； 执行后端可一键切换 pi RPC / dsh headless / opencli / shell。

5.0k 行 Rust 离线可用 dist/TVA.app
它是 pi / dsh 的前端而非产物：本机会话库里没有它的构建记录，按实际来源标注

DingJson

JSON Library · Java 8+ · 零依赖

一个不受 autoType 牵连、也敢拿去跑基准的 Java JSON 库：318 个合规用例全过，流式读数组比 fastjson2 还快。

手写字符级解析器，零运行时依赖——没有第三方 jar，也没有传递 CVE。安全是默认值而不是选项： 深度上限 512（防嵌套 DoS）、HTML 转义（防 XSS）、字符串内裸控制字符按 RFC 8259 拒绝、NaN / Infinity 绝不输出非法字面量。 企业侧给齐 Jackson 同款 DingJsonMapper、@JSONField 注解、JSONPath，以及 eval / isValid / deepCopy 一行式 API； 5,044 行单文件版可以直接拖进任何老项目，不需要构建配置。

07

口径与证据

哪些是数出来的，哪些是推出来的
代码行数
src/ 与 crates/ 下 .rs 的行数合计，不含 target/ 与依赖；JS/TS 同理。共 154,694 行。DingJson 按 src/main 下 .java 计 5,083 行（测试 5,959 行另计），合计 159,777 行。
会话数
pi：~/.pi/agent/sessions/<工作区>/*.jsonl 共 190 个；dsh：~/.dsh/sessions/<工作区>/ 共 68 个，合计 258。目录名即当时的工作目录。
装机
以 /Applications 下实际存在为准：treq、maildesk、artifeeds、RaptorQR Receiver。
公开仓库
以 git remote 指向 github.com/tuean 为准：treq、maildesk、RaptorQR、utools-fd-search、toval、artifeeds、tbas、utools-selfie。DingJson 是 IdeaProjects 下的源码目录，尚无 git 仓库，故不计入这 8 个。
归属
会话目录只能说明「在那个项目里工作过」，不等于逐行归属。treq 的 README 有作者自述作为直接证据，其余按会话密度与提交节奏推断。
例外
TVA 驱动 pi / dsh，但本机会话库里没有它的构建记录，因此单独标注，不算作 pi/dsh 产物。
时间
提交时间与文件时间取自 git / 文件系统；最早的 RaptorQR 提交在 2026-05，最近的在 2026-10-16。
